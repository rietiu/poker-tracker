# 攤牌：記對手手牌＋自動計邊個贏 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** River 動作完、仲有兩個或以上玩家嗰陣，結果嗰步可以（選填）記錄對手手牌；板面齊 5 張而且爭池嘅人手牌全部已知時，顯示「按手牌計：X 贏（牌型）」建議，一撳套用；唔知就照舊手動揀。

**Why（用戶 2026-11-17）：** 「最後 river action 做完後，除了直接問我誰贏，也要記錄對手手牌，但可能也不知道。最好能自動算出誰贏，不過不能也行。」

**Tech Stack:** React 19 + Vite、IndexedDB、vitest（`npx vitest run`；現有 218 個 test；lint baseline 9 errors，唔可以增加）。

## Global Constraints

- 對手手牌完全選填；冇填就畫面、計算、儲存同而家完全一樣（現金局、MTT 都係）。
- 建議永遠只係建議：必須用戶撳「用呢個結果」先寫入 `hand.result`；用戶一直可以手動改。
- 只有「板面 5 張齊」而且「該底池所有未 fold 嘅參與者（包括自己）手牌都已知」先計；任何一個未知就唔出建議（唔估）。逐個底池計（有側池時用 `pots[i].eligible`）。
- 同一張牌唔可以重複：對手選牌時，板面、自己手牌、其他對手手牌都要排除（`InlineCardPicker` 嘅 `usedCards`）。
- 牌格式：點數 + 花色字母，例如 `'As'`、`'Td'`、`'7c'`（同現有 `holeCards`／板面一致）。
- 牌型名稱用英文（High Card / Pair / Two Pair / Trips / Straight / Flush / Full House / Quads / Straight Flush）；介面其他文字中英夾雜，同現有畫面一致。
- 新欄位：`hand.opponentCards = { [position]: [card1, card2] }`；只存兩張都有嘅位置。要進 draft 自動儲存、最終儲存、編輯儲存，並喺 draft 續寫同編輯時載返。

### Task 1: 牌型評估 `src/showdown.js`（純函數）

**Files:** Create `src/showdown.js`、`test/showdown.test.js`

**Interfaces（Produces）:**
- `evaluate7(cards) -> { score: number[], name: string }`：收 5–7 張牌，回傳最佳五張嘅可比較分數（`score` 陣列，逐項比較，大者勝）同牌型名稱。
- `compareScores(a, b) -> -1 | 0 | 1`
- `suggestPotWinners({ board, holes, pots }) -> Array<{ winners: string[], name: string } | null>`：`board` = 5 張牌陣列（唔夠 5 張回全部 null）；`holes` = `{ [pos]: [c1, c2] }`（包括自己）；`pots` = `[{ eligible: [pos] }]`。每個池：所有 `eligible` 都有兩張牌就回 `{ winners, name }`（平手時 winners 多過一個，`name` 係贏家嘅牌型），否則 `null`。
- `describeHand(cards)`：同 `evaluate7(...).name`（俾 UI 顯示自己牌型）。

- [ ] 先寫 test（RED）：每種牌型各一個（包括 A-2-3-4-5 wheel 順、同花順、皇家同花順、四條踢腳、葫蘆比較 trips 再 pair、兩對踢腳、一對踢腳、高牌五張逐張比）；7 張選最佳五張（例如板面係順、手牌令同花）；板面自己玩（board plays）平手；多個贏家；`suggestPotWinners` 有未知手牌回 null、板面唔夠 5 張回全部 null、側池各自 eligible 唔同嘅結果。
